# 停放对话存盘（PARKSAVE / PARKLOAD）

本分支的本地补丁，没有提交上游。作用是让服务重启后接着用重启前停放在内存里的对话，不用从第一个 token 重读。层切分（多卡流水线）也能用。

**默认关闭。** 只有在启动 `serve/server.py` 之前设置了环境变量 `STRATA_PARK_DIR`，才会写盘和读盘。不设置，行为和原版完全一样。

## ⚠️ 硬盘写入与 SSD 寿命

打开以后，**每次优雅停机都会往硬盘写数据**：

- 优雅停机指 `POST /unload`，停机脚本默认走这条路。如果打开了闲置卸载，每次闲置卸载也算一次。
- 写的是停机那一刻内存里停放的对话，上限是会话缓存的预算 `--conversation-cache-mib`。
- 对话越长写得越多。在四颗 GP100 die 上实测：

| 对话长度 | 写入量 |
|---|---|
| 26 万 token | 约 5 GB |
| 60 万 token | 约 10 GB |
| 100 万 token | 约 16.6 GB |

**这会长期消耗 SSD 的写入寿命**，消费级 TLC 盘尤其要注意。估算一下：
- 一段 60 万 token 的长会话，每天优雅停机 3 次，每次都在变长，每年约写 11 TB。
- 常见的 1 TB 消费级 TLC 盘标称寿命约 600 TBW，这样每年用掉大约 2%。
- 停机越频繁、会话越长，用得越多。

只有在重启不频繁、长会话又确实值得保留时才建议打开。

## 为了少写，引擎做了这几件事

1. **没变过的对话不重写。** 每段对话的文件按它的 token 序列命名。上次已经写过、之后没再运行过的对话，文件原样保留，不再写。停机前没有任何请求，就一个字节都不写。
2. **短对话不存。** 少于 `STRATA_PARK_MIN_TOKENS` 个 token 的对话不存盘，默认 16384。短对话重读很快，存盘反而不划算：1K token 的对话存盘要约 240 MB，重读只要约 4 秒。
3. **太久没用的对话不存。** 停放超过 `STRATA_PARK_MAX_AGE_H` 小时的对话，停机时不存，启动时也不加载，默认 48，0 表示不限。它们的旧文件会在下一次停机时删掉。
4. **每段对话只存两个检查点。** 只存最深的一个，用来接着下一轮；再加最浅的一个，就是系统提示结尾的根。不存整条检查点链。

## 怎么用

```
set STRATA_PARK_DIR=<一个写入快的 SSD 上的文件夹>
python serve/server.py ...
```

- 文件夹要放在持续写入快的盘上。实测某些大容量 NVMe 盘持续写入只有 110–200 MiB/s，存一段 60 万 token 的对话要一分半，可能超过停机脚本的等待时间。
- 文件和模型、引擎文件以及全部 `STRATA_*` 开关绑定，`STRATA_PARK_*` 除外。换了引擎或改了开关，旧文件不会加载，下一次停机时覆盖。
- 关掉的方法是不设 `STRATA_PARK_DIR`。关掉以后已有的文件不会自动删除，要手动删掉那个文件夹才能释放空间。

## 实测（Swift 1.5 IQ3_XXS，四颗 GP100 die，层切分 12,24,36）

| 场景 | 结果 |
|---|---|
| 26 万 token 对话从零读 | 296 s |
| 同一对话存盘 / 读回 / 重启后下一轮 | 3.6 s / 3.2 s / 7.2 s（复用 260,834，只读 893） |
| 3 万 token 对话加两段 1K 短对话，停机 | 只写 3 万那段，0.89 GB，0.74 s；两段短的不存 |
| 加载后没有请求就再停机 | 写 0 字节 |
| 3 万那段又运行过再停机 | 写它的新镜像，删掉旧文件 |
| 把停放时间改成 3 天前 | 启动时不加载，下一次停机删除文件 |
| 两次重启后接着聊 | 复用 34,838 token，回复与不重启时逐位相同 |

## 代码位置

- 引擎：`src/program/generate.cpp` 命令循环里的 `PARKSAVE` / `PARKLOAD`；`include/strata/core/conversation_cache.hpp` 里的 `entries()`、`parked_unix`、`disk_name`。
- 服务：`serve/server.py` 里的 `StrataEngine.park_to_disk` / `park_from_disk`。服务会先检查引擎文件里有没有这两个命令，没有就不发，旧引擎不会被关掉。
- 文件格式：每段对话、每颗 die 一个 v1 会话文件（`conversation_file.hpp`，和 `SAVE` 同一种格式和身份校验），外加一个 `park.manifest`（格式 2），写完后一次改名替换旧的。
